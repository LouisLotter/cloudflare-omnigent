The [server Dockerfile](../images/server/Dockerfile) pins source/base inputs and checks the fork Dockerfile mirror. Build arguments may override defaults, so record the values actually used. A matching mirror digest only describes build coupling; it does not mean that different fork commits contain the same fixes. Rebuilds also resolve Debian packages, so source pins alone do not promise identical image bytes.

The computer image pins the same fork commit as the server's default, so a computer's host and the server are built from one source; the selected assembly must still qualify them together.

These are source-inclusion statements. They do not establish runtime behavior on an uninspected image. The main server registers the [Cloudflare launcher](../images/server/cfo_server/launcher.py) (launcher protocol version 1) and [disables GitHub linking](../images/server/cfo_server/app.py). The platform Worker's [internal platform bridge](../worker/src/internal/platform-api.ts) verifies signed launcher calls, but WorkspaceDO is not yet wired to a container and ControlDO's allocator is unbuilt, so launcher calls cannot yet start a computer. Fork capabilities do not make those product integrations complete.

The [wire contracts](../contracts/README.md) define launcher/supervisor protocol version 1, workspace/control interface version 1, workspace/credential format version 1 and checkpoint-policy version 1. Receivers must check the versions they support before effects. Exported JSON Schema covers shape constraints; cross-field refinements and policy/signing/tree calculations also need tests against each actual receiver. The [generic Python fixture tests](../python/tests/test_contracts.py) cover valid/invalid schema fixtures, and the [vector tests](../python/tests/test_contract_vectors.py) use independent reference calculations. They do not prove that an unfinished supervisor applies all refinements. The WorkspaceDO controller refuses unsupported launcher, supervisor, intercept-props and interface versions before any effect. Every command shape it sends is recorded in a [corpus](../worker/test/fixtures/workspace-commands.json) that the supervisor's [actual parser](../images/computer/cfo_computer/contract.py) accepts in the [Python tests](../python/tests/computer/test_workspace_commands.py). That shows the two parsers agree; it is not a test of an assembled supervisor. ControlDO refuses a newer control interface version before parsing, parses every call with the contract, accepts every valid control fixture and refuses every invalid one before any effect, in the Workers runtime. A randomized test checks that the contract's fake ControlDO, which WorkspaceDO's tests use, answers the same calls the same way. Its reconciliation has been tested only against the contract's fake WorkspaceDO, not a deployed one.

Current [CI](../.github/workflows/ci.yml) runs the workspace's Node checks, the root `python/` project, limited canary checks, explicit platform and [web](../worker/wrangler.web.jsonc) bundles, and builds/tests the existing server image targets. Its image suite excludes S3/fault integration and runs without external networking. The [scripts test configuration](../scripts/vitest.config.ts) already includes restore-drill staging tests in Node with fakes. Restore-drill Python and real-platform qualification remain separate; the added CI checks do not change the source pins or assembly status above.

The [canary scanner](../scripts/canary-scan.ts) detects synthetic markers and exact configured values in its supported paths/formats. A clean result is bounded evidence about those values; it is not general proof of no credentials, a whole-repository/history/image scan, or publication approval. Incomplete scans fail.

For every qualification run record platform and fork revisions, actual Worker build/deployment IDs, final server/computer manifest digests and architecture, CLI/SDK/Litestream versions, packaged contract/policy assets, test commands/results, known exclusions and remaining runtime obligations. Image IDs from local tests must be labelled separately from registry manifest digests. Do not use mutable “latest” tags as the record.
